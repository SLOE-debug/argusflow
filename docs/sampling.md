# 公共变化区域与 Paddle OCR

2026-09-17：录制器与 OCR 共用 `argusflow-image` 的像素差分和四连通区域算法。旧共享 GPU 历史采样已删除，当前结构如下：

```text
录像解码 → YCbCr 缩略图 → argusflow-image → 录制选帧
                                      ↑
DxgiFrameSource → FrameSampler → SampledOcr → Paddle
                    精确稳定比较         原图差分 → 完整文字检测 → 受影响文字识别
```

## 职责与精度

- `argusflow-image` 只处理借用的像素视图、通道比较和变化区域，不拥有采集、模型、录像或文件资源。
- 录制器保持原有策略：通道差值至少 12、连通区域至少 6 像素、宽高至少 2，选取最大的 12 个区域；使用录像的 YCbCr 缩略图。
- OCR 使用原始分辨率 RGB，任意通道变化 1 即算变化，不过滤单像素、细线或小区域。
- BGRX 忽略 X；带透明度图像按 OCR 的白底合成语义比较。图像视图支持行跨度和来源内区域。
- 公共算法最多处理 6400 万像素、65536 个有效连通区域，超限明确失败；循环检查取消与总截止时间。

两者复用算法实现，阈值和输入精度分别由调用方决定。录制缩略图不作为 OCR 原图。

## Paddle 的复用行为

引擎工作线程保存上一张成功图像及结果，绑定该引擎固定的模型和预处理配置：

1. 首张图或尺寸改变：正常完整检测与识别。
2. 整图逐像素不变：直接复用检测与识别结果。
3. 图像有变化：仍运行完整文字检测，按当前检测结果处理文字新增、消失和移动。只有四边形完全一致、其外扩 2 像素范围没有变化的文字块才复用识别结果，其他块重新识别。

因此当前优化减少识别工作；局部变化时不会跳过整图检测，也不会把变化碎片裁出来直接当完整文字。缓存图像超过 64 MiB 时不保留；取消和失败不提交缓存。不更改模型参数或 CTC/DB 算法。

## 原始帧区域采样

`FrameSampler::new(Arc<dyn DesktopFrameSource>)` 实现已有 `RegionSource`，交给 `SampledOcr::new(source, engine)`。装配层负责启动和关闭原生帧源，克隆采样器共享 128 MiB 区域图像预算与 8 个并发额度。

采样从完整帧短历史验证指定区域的安静窗口。水位必须健康并达到请求开始时间，历史中该窗口的区域像素必须相同；区域外变化不影响稳定。缺少历史时等待至截止时间，取消、来源重建、越界或故障明确失败。零静默窗口用于动作前重新确认，不额外等待稳定。

采样拒绝已缩小的帧。Windows 示例显式配置最大 3840×2160，超出配置而被缩放的来源无法用于 OCR；调用方不能把缩放图坐标当屏幕物理坐标。原生完整帧流有帧率与历史上限，稳定只表示保留样本及健康水位，不能证明两次采集之间没有短暂变化。

内容令牌保存区域 CPU 像素和来源有效性。后续精确比较相同会话、来源、代际、范围与区域，内容未变则返回 `Unchanged`。来源关闭或重建使旧令牌失效。该路径持续读回完整帧，再按请求裁剪和比较；不再具备旧 GPU 差分管线的按需区域读回特性，未宣称带宽或延迟优于旧实现。

`SampledOcr` 保留每实例八个区域的缓存、在途请求合并、取消传播、屏幕坐标转换与动作前复验。引擎内部另有上述单图文字块缓存。

## 示例

`tests/argusflow-windows/support/sample_ocr.rs` 展示原生帧源、区域采样器和现有 Paddle 引擎的显式装配：

```powershell
cargo run -p argusflow-windows --example sample_ocr -- .deps
cargo run -p argusflow-windows --example sample_ocr -- .deps <source-id> 0 0 800 600
```

第一条列举来源，第二条按参数识别。原生能力只在显式启动后采集，调用方负责 shutdown。

## 删除范围

| 旧代码 | 处理 |
| --- | --- |
| CaptureService、变化订阅、pin_at/pin_after、observe、固定 GPU 版本读取 | 删除，以 FrameSampler 的区域采样满足 OCR |
| DxgiBackend、dirty/move 候选、GPU difference shader、tile/atlas 历史、读取请求队列 | 删除 |
| DesktopBackend、SnapshotPixels、变化日志与缺口契约 | 删除；保留帧源、区域、时钟、像素预算和 RegionSource |
| 仅测试编译的录制 pipeline、帧批次/响应选择、旧像素证据收集 | 删除 |
| 原生录像、录像索引与解码、当前变化选帧、输入日志、UIA 结构证据 | 保留 |
| Paddle 模型加载、推理、查询、坐标和动作前验证 | 保留并接入公共差分 |

这是当前源码清理，不是回退整个 `4a1dece117cb711c60b3aea5c2bfc9db849bd18e` 提交。公共契约和仍使用的基础设施继续保留。历史性能报告见 [旧采样验证](sampling-validation.md)，其中旧管线的测试命令与性能数据不适用于当前实现。
