# 开发启动性能

## 启动链路

`pnpm start` → Tauri CLI → `pnpm dev` → AQL WASM 构建 → Vite；Tauri 在开发服务可访问后运行桌面程序。窗口配置为隐藏，工作台首次渲染并注册关闭监听后才调用 `show()`，随后加载工作区数据。因此终端出现 `Running` 不代表窗口已经显示。

开发终端新增两项累计计时，起点为桌面应用装配，不含编译：

- `[startup] native-ready: … ms`：原生窗口与 WebView 构造完成。
- `[startup] window-shown: … ms`：前端首次渲染、关闭监听注册和显示窗口调用完成。

第一项耗时大应检查原生/WebView 初始化；两项差值大应检查开发服务、前端模块加载和执行；迟迟未出现第二项还可能是前端加载或执行失败。两项都很快而工作区内容仍在加载，则继续检查文档初始化。计时不记录文档内容，发布构建不输出。

## 本次调整

- Vite 预热 `src/main.tsx` 的静态依赖，提前填充转换缓存，减少 WebView 首次请求后的串行转换等待。预热本身仍消耗时间，不表示这些工作被消除。
- 录制回看面板及其播放界面改为首次打开时加载，标题栏录制状态订阅保持原生命周期。
- 启动不再扫描和自动清空 `target`。原先超过 10 GiB 就全量清理，会让后续启动重新编译；改为显式 `pnpm cache:prune` 维护。
- 开发模式开启 Rust 增量编译，保留现有性能敏感代码的优化等级。切换配置后的第一次编译需要建立增量结果；这项调整不解决 `Running` 之后的等待。

默认 5173 端口已有开发服务，完整 `pnpm start` 复测遇到端口冲突。没有关闭既有服务，也没有清除用户的 WebView 或依赖缓存。没有复现用户反馈的长时间冷启动等待，不能据以上局部测量宣称端到端问题已完全解决。

验证使用独立 15173 端口的 Vite Node API、原生进程窗口标题计时、TypeScript 类型检查、录制菜单/回看/工作区测试和 Rust 检查；没有执行浏览器自动化。原生测量仅关闭本次创建的进程。

通过：20 项前端测试、6 项缓存脚本检查、`pnpm typecheck`、`pnpm build`、桌面 crate 的 Cargo build/check/Clippy（`-D warnings`）和工作区格式检查。生产构建仍提示现有大 chunk 警告；Monaco 已动态加载，不能据此将其判为首次窗口显示的阻塞原因。没有运行全工作区 Rust 测试或真实录制验收，本次未修改录制和执行算法。
