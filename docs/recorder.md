# 桌面操作录制器

应用已接入原生视频录制。标题栏的开始、暂停、继续、停止操作同时管理输入日志和视频；事件回看从本地视频按时间解码，不再使用录制时的批量PNG截图队列。输入日志仍为format=2，视频属于独立的分片索引契约。

## 使用

- 标题栏菜单开始录制；视频首帧就绪后才启用输入记录。
- 暂停先停输入并排空通知，然后结束和同步视频片段。继续新建片段，首帧就绪后恢复输入。暂停时间不会拼接成连续画面。
- 停止先完成视频片段，再等待输入日志最终同步。子进程异常、采集失败和磁盘配额不足会报告录制异常，保留已有文件。
- 回看默认对比操作前后的录像像素，按变化区域及连续稳定时间选候选结果；点击/双击最多分析后续2秒，其他操作目前为300ms，在下一次主动操作前截止。窗口通知用于点击结果的确认边界，不冒充绘制完成。键盘默认查看“操作结果”，鼠标默认查看“操作时刻”；只保留这两种画面切换。详见[像素分析算法及实测](recorder-frame-analysis.md)。
- 文本按键逐项保留，时间线操作详情显示原始按键提示；不根据虚拟键推断IME或键盘布局确认后的文本。区间内没有更新的画面时明确提示，不虚构独立结果。
- 最新帧可能还在封装中；无法精确解码时显示错误，可暂停或停止后再次选择操作，不拿旧图代替。
- 重复挂载复用同一取帧任务，快速切换只保留最后一个待处理请求。后端等待解码许可最多10秒、读取响应最多15秒；持续原生故障会明确提示重启，不无限显示读取中。
- 录制使用固定设置，采集 UIA 控件属性与父级信息，保留实际请求区间和来源状态。回看直接展示这些信息；不提供录制设置、外部数据包打开、导出或手动 OCR。

视频包含所选显示器上可见的完整画面，不根据事件后的密码控件识别自动删帧或遮罩。结构观察继续省略密码value；这不等于视频或原始键码已脱敏。

## 本地文件

位置为应用数据目录`recordings/<UUID>/`。本机通常位于`%APPDATA%/com.argusflow.desktop/recordings/`。

| 路径 | 内容 |
| --- | --- |
| session.json / events.afr | 输入时钟、策略与校验追加日志 |
| video/000001/screen.mp4 | 第一个原生H.264分片MP4，持续写盘 |
| video/000001/session.json | 此片段的QPC时钟、尺寸、来源与码率 |
| video/000001/frames.jsonl | 逐帧PTS、时长、呈现/采集QPC、重复标记 |
| video/000001/capture.jsonl | 采集缺口和结束原因 |
| video/000001/ready.json / complete.json | 首帧就绪 / 正常结束并同步 |
| video/000002/... | 暂停继续后的新片段 |
| review-cache/<hash>.png | 可重建回看缓存，最多32张和256MiB |
| review-frames.json | 最多32项磁盘样本→图片映射，重启可复用；视频变化或图片淘汰后重建 |
| review-analysis.json | 最多128项像素分析结果，不保存全量候选图；源文件变化后重建 |

本机录制从“录制历史”打开。原始附件与视频不参与缓存淘汰。缺少complete标记的片段不视为正常结束；只能使用实际解码并通过PTS核对的前缀。输入日志Durability不能证明视频已同步，进程中断验证也不等于断电保证。

## 实现与预算

Rust + DXGI Desktop Duplication + D3D11 VideoProcessor + Media Foundation硬件H.264。采集阶段不读回完整CPU像素，不依赖OBS或打包FFmpeg。回看通过原生Source Reader从关键帧向后解码，核对真实PTS并处理H.264宏块填充区域。[Source Reader文档](https://learn.microsoft.com/en-us/windows/win32/medfound/processing-media-data-with-the-source-reader)、[有效显示区域](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-mt-minimum-display-aperture-attribute)。

| 项目 | 当前限制 |
| --- | --- |
| 显示器 | 适配器0的第一个活动输出；未旋转SDR |
| 视频 | 原生分辨率；最高30fps；目标8Mbps、峰值请求16Mbps的VBR |
| GPU池 | 8张NV12在途纹理+1张静态缓存；应用纹理预算不超过256MiB |
| 静态画面 | 约每秒复用缓存，保留原始呈现QPC，标记repeated |
| 时间索引 | 原始QPC整数；绝对媒体边界按1ms量化，无逐帧累计舍入 |
| 视频磁盘 | 整场约4GiB软配额，暂停继续共享余额；每秒检查；剩余空间低于256MiB停止 |
| 片段 | 最多256段；单段最多1小时，到限后结束并报告状态 |
| 进程 | 输入、视频分为两个隐藏子进程；父进程停止视频最多等5秒 |
| 回看 | 专用线程复用一个Source Reader；只转换最终选中NV12帧；最高3840×2160；PNG缓存32张/256MiB |
| 索引 | 一次缓存一个片段的元数据，最多216000帧，Vec容量约16MiB；二分定位；空闲30秒释放 |
| 输入日志 | 原队列8192条；250ms同步；原始输入最多200万条 |
| 前端 | 有限分页缓存；选中事件独立读取关联操作与 UIA 信息；只持有当前回看图片 |

同步驱动调用仍可能阻塞，因此视频录制运行在独立进程，父进程中断则管道EOF请求停止，视频子进程自行限制5秒收尾。内存预算不包括驱动、WebView、编码器内部资源。回看解码在应用专用线程中，空闲30秒释放解码器，尚未单独隔离解码驱动。

PNG采用原分辨率无损快速编码，视频仍是唯一完整画面归档，不预生成半小时全量PNG。[png快速编码配置](https://docs.rs/png/latest/png/enum.Compression.html)。开发构建对像素转换、PNG及相关依赖启用优化，避免debug热路径拖慢交互；这会增加受影响Rust代码的编译时间。耗时测量见[验证记录](recorder-validation.md)。

## 验证与限制

打包EXE原生测试通过：两个视频片段分别开始/停止、末帧按PTS解码、输入暂停恢复。索引测试覆盖帧前后选择、暂停空洞和半条索引尾部；缓存测试验证淘汰不触碰原始证据。前端测试覆盖视频取帧、缺失提示及切换录制后的迟到结果隔离。未运行浏览器自动化，也未把这些测试当作Win搜索Notepad的视觉验收。

当前不支持多屏同时录制、旋转、HDR、音频或DXGI独立硬件指针合成，不自动恢复热插拔。已有PNG会话不会凭空拥有视频，也未添加旧画面回退。30分钟真实长测尚未完成；此前10分钟资源实测和30分钟合成时间轴见[原型验证](recorder-video-prototype.md)。具体格式见[数据格式](recorder-format.md)。
