# 录制候选区域与停止后 GPU 精确化

## 当前管线

录制时：DXGI 脏区和移动目标区 → 三槽异步区域读回 → 有界冻结像素队列 → 不比较像素的不可变快照更新 → 候选区域 PNG。

停止时：排空输入与已提交图像 → 发布可回看的候选归档 → 独立硬件 D3D11 Compute Shader 比较 → 去重、收紧区域、重建检查点和依赖 → 重新关联事件 → 保存精确索引 → 删除旧候选图像。

实时桌面订阅发布原生候选区域，不再执行 CPU 精确差分。WGC/OCR 原有实时精确变化语义保持独立；此次延后的是录制桌面的精确化。

## GPU 实现

纯 Rust 调用 D3D11，内嵌 HLSL `cs_5_0`。独立硬件 FL11 设备及 context，不争用实时采集设备。每组 64 个线程检查一个 32×32 像素块，逐像素 XOR 比较有效通道，以组共享原子操作收紧边界。BGRX 忽略保留字节；RGBA 比较全部四通道。只读回每块 16 字节的矩形结果。

输入来自已落盘区域，每次上传一个候选区域的前后像素；GPU 不是常驻整场录像的缓存。离线 Map 允许等待 GPU，实时采集线程不参与等待。未使用 C++、阈值、稀疏采样、哈希替代或软件 GPU 回退。

## 数据与失败语义

- `screen.refinement` 明确区分 `pending`、`complete`、`failed`；候选范围不能标记为精确变化。
- `screen.duration_us` 保留录制时长，重复末帧被删除后仍保留静止尾段。
- 每来源首次及代数/拓扑变化重新建立基准；精确化后按 120 次变化或 2 秒建立检查点。
- 原帧 ID、呈现时间、来源、代数保留；删除重复帧后重建事件引用。
- GPU 失败时返回可读的原始候选归档和失败状态。精确化失败不标记成采集漏帧。
- 新区域使用未引用的区域 ID。精确索引发布前不删除候选像素；文件发布失败时保留两代像素供当前会话重试。
- DXGI 累计多帧仍报告采集不完整，GPU 无法恢复不存在的中间呈现。

## 验证（2026-09-09）

- 实际硬件 shader 对照 CPU：单像素、32×32 边界、非整块尺寸、负坐标、RGBA alpha、BGRX 保留字节通过。
- 合成 `notepadd`：17 次候选呈现含 8 次重复重绘，GPU 得到 1 基准＋8 次不同变化；落盘重建逐像素一致，5 秒时长不缩短。模拟 GPU 故障后原候选可读；重新处理并删除旧文件后依赖仍可重建。
- 三次真实桌面动态录制：候选 50/47/48 帧，精确化 44/47/47 帧，时长约 5.037/5.043/5.037 秒，采集与精确化均完整。原生窗口每 50ms 请求重绘，实际呈现由系统决定；这个测试不把重绘次数当作呈现次数。
- Capture 8、Recorder 39、Vision 39、Windows 27 项常规 Rust 测试通过；两个 GPU 测试及持续录制测试显式执行通过；前端录制器 13 项测试、TypeScript 构建与 Tauri 检查通过。

尚未在用户指定的 GTX 1080 实机完成 4K 性能验收。后处理有上传、PNG 解码和重新编码成本，停止后会显示“正在整理画面并保存”。
