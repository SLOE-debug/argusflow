# ArgusFlow 前端开发规范

必须同时遵守 [通用编码与架构规范](coding-standards.md)：适度抽象、避免过度抽象、高可用、高内聚、低耦合。

## TypeScript 开发规范

- 代码以强类型为先，优先使用接口、泛型、枚举、只读类型、映射类型、条件类型和明确的领域模型。
- 充分使用 TypeScript 类型推导、泛型约束、`satisfies`、判别联合、类型守卫和类型化注册表，避免 `any`、无约束类型断言、弱类型服务定位和字符串式分发。
- 运行时协议、业务状态、节点类型、事件类型和注册键不得写成散落字符串；应来自枚举、判别联合、只读清单或类型化 key。
- 每个模块和 React 组件只承担一种明确职责；状态编排、数据转换、业务决策、画布交互和视觉渲染不得长期混在同一组件或文件中。
- 跨模块调用必须依赖稳定接口、领域类型或门面；底层通用模块不得反向依赖具体业务实现，同层业务模块不得绕过公共契约互相读取内部状态。
- React 组件优先通过明确的 `Props` 类型和回调契约通信；可派生状态不得重复存储，可复用状态逻辑应下沉到 Hook，可复用纯转换应下沉到普通模块。
- 数组、对象和配置表在不需要修改时使用 `readonly`、`ReadonlyArray` 或 `as const`；不得把可变集合直接暴露为公共契约。
- JSX 必须保持可读：多属性元素分行书写，每个属性独占一行；复杂条件、长回调和重复结构必须提取为具名变量、函数或子组件，禁止持续堆叠超长单行 TSX。
- Tailwind `className` 可以保留在组件内，但长类名应按组件层级合理换行；不得为了缩短行宽退回普通 CSS，也不得把多个职责压缩成难以审查的一行。

## TypeScript 模块边界

- `src/flow` 只保存与业务无关的画布内核、几何、路由、选择和状态契约，不得 import `features` 或具体工作流组件。
- `src/features` 保存工作流领域模型、API 和状态编排，不得承载具体页面布局或视觉样式。
- `src/components` 通过 `flow` 与 `features` 的稳定契约渲染业务界面；组件不得绕过公开状态操作直接修改 Store 内部结构。
- `Input`、`Select`、`Textarea`、`Checkbox`、`Radio`、`Switch`、`FormField` 等通用表单组件必须放在 `src/components/ui` 下；业务组件不得重复实现同类基础控件或复制其公共样式。
- `src/components/ui` 只保存与业务无关的强类型 UI 基础组件，不得 import `features`、`flow` 或具体工作流组件；业务差异通过明确的 Props 和组合内容传入。
- 不同 Feature 之间禁止直接读取内部实现；跨 Feature 通信必须经过类型化契约、门面、事件或注册表。

## 前端协作与可用性

- 通用 UI 只负责交互与展示契约，Feature 负责领域规则和状态编排，API 适配模块负责传输及协议转换；页面和组件不得直接处理 COM、CDP、Python 或其他后端实现细节。
- 外部能力通过类型化 API 或适配契约接入；新增模块通过 Props、回调或明确的领域契约组合，不侵入通用组件和画布内核。
- 异步请求明确加载、成功、失败和取消状态；组件卸载或请求被替代时释放订阅并取消可取消任务，防止旧结果覆盖新状态。
- 对独立功能设置适当的错误边界，失败反馈应允许用户理解当前状态和可执行操作；不能让局部失败导致整个工作区不可用。

## 前端样式

- **前端样式必须优先使用 Tailwind CSS（twcss）工具类。** 布局、尺寸、字号、间距、颜色、边框、圆角、阴影、Flex/Grid、对齐、响应式和常规交互状态不得新写普通 CSS。
- **除非样式非常复杂且 Tailwind CSS 无法清晰、可靠地表达，否则禁止新增普通 CSS。** 允许例外的场景仅限复杂 SVG 绘制、关键帧动画、必须依赖伪元素的复杂效果等，并应将原生 CSS 控制在最小范围内。
- 不得为了缩短 `className`、沿用旧习惯或追求表面整洁，把本可直接使用 Tailwind CSS 表达的样式抽成普通 CSS 类或新增 CSS 文件。
- 修改已有前端界面时，应同步评估所触及的普通 CSS；能够直接迁移为 Tailwind CSS 的部分应随本次改动迁移，不得继续扩张普通 CSS。

## UI 与目录重构规则

- 通用按钮、图标按钮、分裂按钮、表单字段、下拉菜单、提示框和确认对话框统一从 `src/components/ui` 复用；业务组件不得重复实现同类基础控件。
- 业务组件原则上不得新增裸 `<button>`、`<input>`、`<select>`、`<textarea>`；仅保留标签页、画布交互和其他具有明确业务语义的例外，并通过注释说明原因。
- `src/components/workflow` 按工作区、工具栏、停靠面板、检查器、节点字段、节点面板、画布和执行视图拆分；不得把不同职责重新堆回入口文件。
- `src/features/workflow` 按模型、API、Studio 编排、节点、值表达式、组件、执行和输入契约拆分；页面布局与视觉样式放在 `src/components`。
- `src/flow` 只保留业务无关的画布内核、交互、状态、路由、几何、选择和视口模块；不得依赖 `features` 或工作流组件。
