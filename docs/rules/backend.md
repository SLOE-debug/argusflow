# ArgusFlow 后端开发规范

必须同时遵守 [通用编码与架构规范](coding-standards.md)：适度抽象、避免过度抽象、高可用、高内聚、低耦合。

## Rust 开发规范

- Rust 同样以强类型为先，优先使用 `struct`、`enum`、Trait、泛型、关联类型、Newtype 和明确的领域模型表达约束，不用字符串、裸数字或无语义元组模拟业务类型。
- 有限状态、事件、命令、节点类型和错误种类必须优先建模为枚举，并使用穷尽 `match` 处理；不得依赖字符串比较或默认分支吞掉新增状态。
- 不变量应尽量在构造阶段建立；需要校验的领域值应通过私有字段、构造函数或 `TryFrom`/`FromStr` 形成有效类型，避免无效状态在系统中传播。
- 可失败操作必须返回明确的 `Result`，可缺失值使用 `Option`；生产代码不得随意 `unwrap`、`expect` 或 `panic!`，只有测试或已证明的不变量可以使用，并应说明依据。
- 所有权和借用关系必须清晰。默认不可变，优先传递引用、切片和迭代器；不得为了绕开借用设计而无意义 `clone`，共享可变状态必须限制在明确的并发或生命周期边界内。
- Trait 只用于真实行为边界或多实现契约；能使用静态分发时优先泛型，只有确需运行时多态时使用 `dyn Trait`，不得提前制造空 Trait 或单实现抽象层。
- 模块必须保持高内聚、低耦合：领域模型、校验、执行、平台适配和 I/O 分层放置；核心 crate 不得反向依赖 Tauri、Windows 或具体平台实现。
- `lib.rs`、`main.rs` 和 `mod.rs` 优先只保留模块声明、公共导出和启动编排；复杂实现应进入具名模块。
- 公共 API 必须最小化，优先 `pub(crate)` 或私有；公开结构的字段应谨慎暴露，优先通过只读访问器和领域方法维护不变量。
- 并发边界应由类型体现，明确 `Send`、`Sync`、任务所有权和取消语义；不得用全局可变状态或隐式锁顺序传递协议。
- `unsafe` 只能封装无法由安全 Rust 表达的最小边界，必须记录安全不变量，并向外提供安全接口；不得扩大 `unsafe` 作用域以图省事。
- 热路径应避免重复分配、无意义克隆和临时集合；优化必须基于明确的调用频率和数据规模，不得牺牲领域边界换取未经验证的微优化。

## Rust crate 边界

- `argusflow-core` 只保存跨平台领域模型、动作契约、错误和执行事件，不得依赖 Tauri、Windows API、浏览器或具体运行时实现。
- `argusflow-runtime` 可以依赖 `argusflow-core` 编排校验、调度和执行，但不得反向把运行时状态泄漏到核心领域模型。
- Windows、浏览器、视觉和 Agent crate 通过核心 Trait 与类型协作，不得互相静态依赖具体实现或复制协议结构。
- `src-tauri` 只负责桌面应用装配、命令适配和状态托管；领域校验和执行规则必须下沉到对应 crate。

## 能力模块职责边界

下表约束对应模块存在时的职责，不要求提前创建空模块或抽象层。模块内部可以组织具体实现，但公开契约不得泄漏实现细节。

| 模块 | 自身职责 | 不得承担或直接依赖的细节 |
| --- | --- | --- |
| core | 跨平台领域类型与必要的能力契约 | 不知道 Windows、CDP、Paddle 等具体实现 |
| aql | 查询语言的模型、解析与语义，通过查询能力契约求值 | 不知道 COM、CDP、Python；具体查询后端由适配层接入 |
| capture | 采集能力、帧数据与采集生命周期 | 不知道 OCR、workflow、recorder 等消费方；通过采集后端隔离平台实现 |
| windows | Windows 平台能力与系统资源管理 | 不知道 workflow 节点；不承载工作流决策 |
| vision | 图像分析与识别能力 | 不负责 DXGI 采集；通过帧或图像契约接收输入 |
| runtime | 校验、调度与执行编排 | 不直接调用 COM、CDP protocol 或 Python；通过能力契约执行 |
| recorder | 录制生命周期及录制事件的组织 | 不直接调用 Win32 Hook API；通过输入事件来源契约接收事件 |

- COM、CDP、Paddle、Python、DXGI、Win32 Hook 等实现细节由对应的平台、协议或能力适配模块封装，不得渗透到调用方的领域模型。
- 例如采集模块输出帧，视觉模块消费图像，运行时协调能力；采集模块不触发 OCR，也不识别工作流节点。
- 例如录制模块消费输入事件，Windows 适配模块管理 Hook 的安装、回调和释放；录制模块不持有原生 Hook 句柄。
- 新能力接入时，在装配边界连接实现与契约，不得让已有模块为了识别新实现而增加具体后端分支。

## 后端生命周期与可用性

- 外部进程、设备、连接和系统句柄由所属适配模块管理，明确创建、就绪、失败、取消和释放过程，不把资源管理责任隐式转嫁给上层。
- 调度与执行必须传播取消信号、限制并发，并以明确的执行结果报告失败；外部服务或进程异常不得造成任务永远处于运行中。
- 执行事件与诊断应关联具体任务或资源，便于定位故障；只在语义允许时重试，不自动重复有副作用的动作。
- `argusflow-runtime` 按执行、校验、组件、资源和命令职责组织模块；`lib.rs` 只负责模块声明与稳定公共导出。
