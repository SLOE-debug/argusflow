# 录像像素变化选帧

2026-09-13。目标是从已保存录像中找出操作后的可见变化结果；不再把固定延迟或无新帧间隔当作图像比较。

## 调研与选择

- Context7查询OpenCV 4.13文档，核对差分、阈值与连通区域统计的职责。连通分量可提取面积和边界框，用于过滤细小噪声及定位变化区域。[OpenCV形状分析](https://docs.opencv.org/4.13.0/d3/dc0/group__imgproc__shape.html)
- 缩小时区域平均有助于抑制混叠。实现使用Rust分块求均值，不引入OpenCV动态库。[OpenCV缩放](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html)
- NV12由Y平面和交错UV平面组成，可直接提取亮度及色度。仅比较亮度会漏掉等亮度颜色变化，因此保留三个通道。[Microsoft NV12布局](https://learn.microsoft.com/en-us/windows/win32/medfound/recommended-8-bit-yuv-formats-for-video-rendering)
- DXGI dirty/move rectangles可优化采集阶段，但可能合并扩大更新区域，也不是录像里天然存在的视觉证据。当前算法读取历史视频像素，不假定旧录像具有未保存的dirty rectangles。[Desktop Duplication](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)

## 公共模块（2026-09-17）

差分和四连通算法已提取到 `argusflow-image`，录制器通过 `video/analysis/regions.rs` 配置原有过滤策略。Paddle 复用同一实现，但使用原始 RGB 和单像素精确策略；整图不变直接复用，有变化时完整检测后重识别受影响文字块。细节见 [公共差分与采样](sampling.md)。派生分析缓存版本已更新，原始录像不受影响。

## 当前路径

点击/双击回看默认展示按下前的最后一张录像帧，并按关联Raw鼠标按下记录叠加目标坐标；“操作结果”单独切换到下述算法结果。目标帧不使用上一条键盘事件的截图。标记只减视频屏幕原点，不重复乘DPI，不改写PNG；缺失坐标时不猜测目标。

1. 从Interaction.from_qpc之前的实际呈现帧建立基准。结果时间上限仍按操作结束和下一次主动输入确定；点击/双击最多观察后续2秒，其他操作目前为300ms。
2. 窗口通知仅用于设定点击的最早确认时间，跟随后续前台窗口切换；300ms不再直接指定结果帧。
3. 原生Source Reader顺序解码操作区间，跳过重复心跳。直接从NV12按偶数块求均值，生成不超过640×400的YCbCr小图，不把每个候选帧转成全尺寸RGB或PNG。
4. 任一通道差值达到12形成变化掩码；4连通区域中面积不足6个小图像素、仅一像素宽/高的细线不驱动选帧。最多返回12个较大区域，映射回原图坐标。阈值为当前工程启发式，不是文档提供的普适准确率保证。
5. 相对操作前基准判断是否有明显变化，相对候选图判断变化是否继续。明显变化重置候选；候选像素连续至少200ms没有新的明显变化，且已越过窗口确认边界，才报告settled。持续产生帧不妨碍像素稳定判断。
6. 区间结束仍变化则报告changing，未检测到明显变化则报告no_change。只把最终候选PTS解码为原尺寸RGBA并保存无损PNG，右侧显示该帧及分析状态。

## 预算与持久化

- 单次区间最多121条帧索引，超限明确报错，不静默跳过长区间再声明已完整分析。该上限不是整段录像时长上限。
- 同时仅保留基准、参考、当前三个小图，最大约2.2MiB；差分掩码和连通遍历另有有界临时内存。解码器及驱动内部内存不计入此数。
- `review-analysis.json`最多128项，读取预算512KiB。键包含算法版本、视频/逐帧索引/片段元数据的文件身份以及操作区间，变化即失效。缓存保存序号、区域和状态，不保存候选全图。
- 原尺寸派生PNG继续使用32张/256MiB预算。分析和PNG可跨重启复用；分析映射保留而PNG已淘汰时，只需重建选中PNG。两个缓存均不作为原始证据导出。
- 元数据帧索引仍最多216000条，单片段缓存、二分查找，空闲30秒释放。

## 边界

这是可见变化候选算法，不证明业务完成或变化的因果归属。独立背景动画、极小的业务变化和超过窗口上限的慢响应仍需查看原时刻或后续帧；粗粒度连通区域不是像素精确分割。原视频仅能提供实际采到并写入的帧，算法不能补造采集缺口，也不把有损H.264声明为逐像素无损证据。此次未进行浏览器或应用窗口点击验收。
